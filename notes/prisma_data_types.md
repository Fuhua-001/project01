# คู่มือการใช้งานชนิดข้อมูล (Data Types) ใน Prisma
*วันที่บันทึก: 24 กรกฎาคม 2026*

เวลาที่เราออกแบบฐานข้อมูลในไฟล์ `schema.prisma` สิ่งที่สำคัญที่สุดคือการเลือก "ชนิดข้อมูล" ให้เหมาะสมกับสิ่งที่เราจะเก็บครับ เพราะถ้าเลือกผิดอาจทำให้ระบบทำงานผิดพลาดได้

---

## 1. ชนิดข้อมูลพื้นฐาน (Core Data Types)

*   **`String`** = **ตัวอักษรหรือข้อความ** 
    - **วิธีใช้:** เก็บข้อมูลอะไรก็ได้ที่เป็นข้อความยาวๆ หรือสั้นๆ (ตัวเลขที่เอาไปคำนวณไม่ได้ เช่น เบอร์โทร ก็ควรเป็น String)
    - **ตัวอย่าง:** ชื่อ, นามสกุล, อีเมล, เบอร์โทรศัพท์, รหัสไปรษณีย์

*   **`Int`** = **ตัวเลขจำนวนเต็ม** (ไม่มีทศนิยม)
    - **วิธีใช้:** เก็บข้อมูลตัวเลขที่นำไปบวกหรือลบได้ หรือใช้เป็นลำดับ
    - **ตัวอย่าง:** รหัส ID, อายุ, จำนวนสินค้าในสต็อก, ยอดผู้เข้าชม

*   **`Float`** = **ตัวเลขมีทศนิยม**
    - **วิธีใช้:** เก็บตัวเลขที่มีความละเอียดระดับจุดทศนิยม
    - **ตัวอย่าง:** ราคาสินค้า, ยอดเงิน, น้ำหนัก, ส่วนสูง

*   **`Boolean`** = **ค่าความจริง (True / False)** 
    - **วิธีใช้:** เก็บข้อมูลที่มีแค่ 2 สถานะ คือ ใช่/ไม่ใช่, เปิด/ปิด
    - **ตัวอย่าง:** สถานะการใช้งาน (`isActive`), สิทธิ์แอดมิน (`isAdmin`)

*   **`DateTime`** = **วันและเวลา**
    - **วิธีใช้:** เก็บข้อมูลวันที่และเวลา
    - **ตัวอย่าง:** วันที่สมัครสมาชิก, วันที่ทำรายการ, วันเกิด

## 2. สัญลักษณ์พิเศษเสริมพลัง (Attributes)
นอกจากใส่ชนิดข้อมูลแล้ว เรายังสามารถเอาสัญลักษณ์เหล่านี้ไปต่อท้ายเพื่อเพิ่ม "กฎเกณฑ์" ให้กับคอลัมน์นั้นได้:

*   **`?` (Optional)** = **ไม่บังคับกรอก**
    - **ตัวอย่าง:** `company String?` แปลว่าลูกค้าคนนี้จะใส่ชื่อบริษัทมาให้หรือไม่ใส่ก็ได้ (เป็นค่า null ได้)
*   **`@id`** = **รหัสประจำตัวหลัก (Primary Key)**
    - **ตัวอย่าง:** `id Int @id` แปลว่านี่คือเลขประจำตัวของข้อมูลแถวนี้ ห้ามซ้ำกันเด็ดขาด
*   **`@unique`** = **ห้ามมีข้อมูลซ้ำในระบบ**
    - **ตัวอย่าง:** `email String @unique` แปลว่าระบบจะไม่ยอมให้ใครสมัครใช้อีเมลนี้ซ้ำอีก
*   **`@default(...)`** = **ค่าเริ่มต้น (ถ้าผู้ใช้ไม่กรอก ระบบจะยัดค่านี้ให้เอง)**
    - `@default(autoincrement())` = รันตัวเลขขึ้นเองอัตโนมัติ (1, 2, 3...)
    - `@default(now())` = ใส่วันและเวลาของวินาทีปัจจุบันให้เลย
    - `@default(false)` = เริ่มต้นให้เป็น False ไว้ก่อน
*   **`@updatedAt`** = **อัปเดตเวลาอัตโนมัติ**
    - ระบบจะเปลี่ยนเป็นเวลาปัจจุบันให้เองเสมอ เมื่อมีการสั่งแก้ไขข้อมูลในแถวนี้

## 3. ตัวอย่างการนำมาใช้งานจริง (CRM Schema)
ลองดูตัวอย่างการออกแบบตารางพนักงาน (Employee) และลูกค้า (Customer) ที่ใช้ Data Types และ Attributes แบบจัดเต็ม:

```prisma
model Employee {
  id        Int      @id @default(autoincrement()) // รันเลข 1,2,3... ให้อัตโนมัติ
  email     String   @unique                       // อีเมลพนักงาน ห้ามซ้ำ
  password  String                                 // รหัสผ่าน บังคับว่าต้องมี
  nickname  String?                                // ชื่อเล่น มีหรือไม่มีก็ได้
  salary    Float    @default(15000.0)             // เงินเดือนเริ่มต้นที่ 15,000.0
  isAdmin   Boolean  @default(false)               // เริ่มต้นคือเป็นพนักงานธรรมดา (false)
  createdAt DateTime @default(now())               // บันทึกเวลาที่เพิ่มพนักงานเข้าสู่ระบบ
}
```

**วิธีใช้งานร่วมกับโค้ด Next.js:**
เมื่อเราออกแบบตารางเสร็จและสั่ง `npx prisma db push` แล้ว ในหน้าโค้ดเราสามารถเรียกใช้งานได้ง่ายมากครับ เช่น:

```typescript
// ตัวอย่างโค้ดสร้างพนักงานใหม่ (เราไม่จำเป็นต้องกรอก id หรือ createdAt เลย เพราะเราใส่ @default ไว้)
await prisma.employee.create({
  data: {
    email: "test@company.com",
    password: "hashed_password",
    // salary ก็ไม่ต้องกรอก เพราะเดี๋ยวระบบยัด 15000.0 ให้เอง!
  }
})
```
จะเห็นว่าการออกแบบ `schema.prisma` ที่ดี จะช่วยให้เราเขียนโค้ดฝั่งเว็บไซต์ได้สั้นลงและลดความผิดพลาดได้มหาศาลเลยครับ!
